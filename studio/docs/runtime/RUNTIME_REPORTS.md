# Runtime Reports

## Purpose
Runtime reports are deterministic local JSON files produced by the Studio OS runtime console. They make the foundation inspectable by humans, automation and a future dashboard without activating external providers or deployments.

## Report Location
Reports are written to:

```text
runtime/reports/
```

The runtime index is written to:

```text
runtime/runtime-index.json
```

The complete `runtime/` tree is local generated output and stays ignored by Git.

## Required Report Shape
Each runtime report uses the same top-level structure:

```json
{
  "timestamp": "2026-05-28T00:00:00.0000000Z",
  "source": "studio-console:status",
  "status": "ok",
  "summary": "Human-readable summary.",
  "checks": [],
  "warnings": [],
  "errors": [],
  "nextRecommendedAction": "Concrete next action."
}
```

## Report Files
| File | Meaning |
| --- | --- |
| `studio-status.json` | Aggregated runtime status across config, providers, contracts, deployments, projects, docs, events and telemetry. |
| `config-status.json` | JSON readability and top-level structure for config files. |
| `provider-status.json` | Provider configuration state, missing credential environment variables and blocking flags. |
| `validation-status.json` | Output and exit state from the validation command chain. |
| `telemetry-status.json` | Telemetry log state and latest entry when available. |
| `event-status.json` | Event log state and latest entry when available. |
| `contract-status.json` | Contract and schema file existence, JSON validity, expected structure and modification time. |
| `deployment-status.json` | Deployment profile readiness metadata without deployment execution. |
| `documentation-status.json` | Required governance and runtime documentation state. |

## Runtime Index
`runtime/runtime-index.json` summarizes:

- latest status report
- latest health report
- latest validation report
- latest telemetry entry
- latest event entry
- known projects
- known providers
- known agents
- last documentation sync report

The index is regenerated by console commands and is the preferred entry point for a future dashboard.

## Security Boundary
Reports must not contain API tokens, OAuth values, private keys or provider response payloads. Provider inspection is limited to configured or missing environment variable names and non-secret metadata.

## Operational Rules
- Reports may show warnings for non-core provider gaps.
- Reports must not create fake success states.
- Reports must reflect missing logs as `warning` or `not-initialized`, not as successful activity.
- Runtime report writers must use `StudioRuntime.psm1` helpers instead of duplicating file IO logic.
