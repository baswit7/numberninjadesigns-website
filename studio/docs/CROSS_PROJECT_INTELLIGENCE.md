# Cross-Project Intelligence

## Doel
Cross-Project Intelligence zorgt dat de factory slimmer wordt met elk project. Launches, bugs, prompts, UX patronen, SEO resultaten, API failures en architecture decisions worden omgezet in herbruikbare intelligence.

## Intelligence Sources
| Source | Extracted Intelligence |
| --- | --- |
| Releases | successful launch patterns, rollback gaps, gate failures |
| Experiments | profitable products, pricing signals, channel fit |
| Incidents | recurring bugs, unstable integrations, prevention rules |
| Prompts | high-performing prompt blocks, failure patterns, token waste |
| Architecture | reusable system boundaries, scaling risks, shared module candidates |
| UX | high-converting flows, friction patterns, mobile failures |
| SEO | content structures, keyword clusters, ranking movement |
| APIs | stability, rate limits, fallback patterns, auth issues |
| Automation | repeatable workflows, retry behavior, manual effort removed |

## Pattern Types
| Pattern | Promotion Criteria |
| --- | --- |
| Launch Pattern | improved readiness, clean release and measurable outcome |
| Product Pattern | commercial validation or strong market signal |
| Architecture Pattern | reused successfully or reduces complexity |
| Prompt Pattern | high success, low correction rate and acceptable token cost |
| UX Pattern | improves activation, clarity or conversion |
| SEO Pattern | measurable ranking, traffic or content velocity improvement |
| Debug Pattern | repeated root cause with prevention rule |
| API Pattern | stable integration design with fallback |
| Automation Pattern | repeated manual process safely automated |

## Intelligence Extraction Pipeline
```text
event or artifact
  -> classify domain
  -> extract structured learning
  -> attach evidence and confidence
  -> compare with existing patterns
  -> promote, merge or reject
  -> recommend propagation targets
  -> update gate, prompt or playbook
```

## Reusable Intelligence Index
| Index Field | Purpose |
| --- | --- |
| pattern_id | stable reference |
| domain | launch, revenue, SEO, UX, API, debug, architecture, prompt |
| trigger | when this pattern applies |
| solution | recommended approach |
| constraints | when not to use it |
| evidence | source project, metric, release or incident |
| confidence | evidence strength |
| reuse_count | adoption measure |
| owner | accountable curator |
| status | proposed, active, deprecated or superseded |

## Project-To-Project Propagation
| Trigger | Propagation |
| --- | --- |
| New project matches known domain | recommend relevant architecture, UX, SEO and revenue patterns |
| API instability discovered | warn projects using same provider |
| Launch playbook validated | apply to similar release pipelines |
| Prompt block improved | update agent task templates |
| Repeated bug class found | add prevention gate across affected projects |
| SEO structure succeeds | suggest content system to related projects |
| Conversion pattern wins | test on projects with similar funnel |

## Anti-Pattern Handling
Anti-patterns are never deleted silently. They are:
- recorded with failure mode;
- linked to affected projects;
- given prevention rule;
- assigned severity;
- superseded only with better evidence.

## Promotion Rules
| Promotion Level | Requirement |
| --- | --- |
| Candidate | one strong success or one repeated signal |
| Active Pattern | repeated success or high-impact validated result |
| Factory Default | used successfully across multiple projects |
| Deprecated | lower success, higher cost or replaced by better pattern |
| Blocked Pattern | creates security, quality or scaling risk |

## Optimization Recommendations
The system should recommend:
- shared module extraction;
- prompt reuse or rewrite;
- release gate strengthening;
- API fallback design;
- SEO content cluster reuse;
- UX flow reuse;
- architecture simplification;
- automation of repeated work.

## Compound Advantage Standard
The factory has compound intelligence when the cost of starting the next project decreases while launch quality, revenue confidence and operational reliability increase.
