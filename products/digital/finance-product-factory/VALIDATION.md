# Validation

## Validation layers

1. `src/contracts/validation.js` enforces versioned JSON schemas and semantic invariants.
2. `src/engines/validation-engine.js` validates configuration, rereads generated XLSX/OOXML, and constructs compatibility reports.
3. `src/factory-runtime.js` turns those reports into generation/quality/package gates and can execute a compatibility probe before packaging.
4. `src/commercial/listing-image-engine.js` and `src/commercial/package-engine.js` validate physical PNGs, required package paths, hashes, and final ZIP contents.
5. `scripts/generate-native-release.mjs` provides the certified Excel Desktop probe and review-candidate evidence path.

## Public validation API

| Export | Responsibility |
| --- | --- |
| `ALLOWED_CAPACITIES` | `50`, `100`, `250`, `500`, `1000`. |
| `VALIDATION_STATUSES` | `PASS`, `FAIL`. |
| `validateConfiguration()` | Product identity, catalog support, capacities, year/market/filename/categories. |
| `inspectWorkbook()` | ExcelJS reread plus JSZip/OOXML structure checks. |
| `makeValidationReport()` | Strict normalized `ValidationReport`. |
| `compatibilityReport()` | Declared target results from structural state and supplied evidence. |

## Configuration and workbook checks

Preflight validates definition, configuration, semantic references, localization, theme, and currency profile. A failure blocks preview/generation.

After generation, `inspectWorkbook()` requires plausible local XLSX bytes and checks:

- exact sheet names/order;
- live formulas and no `#REF!`;
- currency formats, panes, filters, and required validations;
- per-sheet/global metrics;
- required OOXML parts, worksheet XML, relationships, formula/validation/filter/pane markers, and internal relationship targets.

Any issue throws `WORKBOOK_VALIDATION_FAILED` before compatibility or packaging.

Structural reread proves internal XLSX coherence. It does not calculate formulas or certify a spreadsheet application.

## Compatibility model

The contract schema can represent `excel-desktop`, `excel-web`, `libreoffice`, and `google-sheets`. Current product definitions declare only `excel-desktop`, minimum version 2019, with recalculation required. Excel for the web, LibreOffice, and Google Sheets are not release-certified.

For each declared target:

- supplied evidence is copied as version/status/checks/limitations;
- structural failure without evidence becomes `FAIL`;
- structural pass without native evidence becomes `PARTIAL` with an explicit missing-native-open/save limitation.

Aggregate status is `FAIL` if any target fails, `PASS` only when every target passes, `NOT_TESTED` only when all are untested, otherwise `PARTIAL`.

## Compatibility probe sequencing

`FinanceProductFactoryRuntime.generate()` accepts `compatibilityEvidence` or `compatibilityProbe`:

1. preflight, generation, and structural reread complete;
2. the probe receives definition, configuration, validation report, timestamp, and a copied exact workbook byte sequence;
3. the runtime validates the returned evidence shape;
4. compatibility and quality reports are built;
5. the original generated bytes are packaged.

This ordering ensures native evidence exists before a review-ready manifest is created. The controlled workbook test hashes the probe input and packaged workbook to prove byte identity.

Direct `compatibilityEvidence` remains supported for callers/tests, but it is not independently authenticated. Release policy therefore accepts only traceable evidence produced by the native CLI.

## Native Excel gate

The native CLI probe runs `scripts/excel-open-save-smoke.ps1` and requires:

- read-only open with macros/events/alerts/link updates disabled;
- automatic calculation and `CalculateFullRebuild`;
- no external Excel workbook links;
- no circular reference;
- no calculated formula-error cells;
- native formula count equal to the structural count;
- successful `SaveCopyAs` and native reopen;
- successful ExcelJS/OOXML reread of the Excel-saved copy.

It records Excel/calculation versions, checks, paths, sizes, hashes, limitations, and error detail. The CLI then verifies that the original native-tested bytes are unchanged inside the commercial package.

The script records but does not numerically enforce the Excel 2019+ version floor; release review must verify the recorded environment.

## Release gates

- Validation `FAIL` stops runtime generation or produces a blocked QA manifest for direct package fixtures.
- Quality or compatibility `FAIL` makes `GeneratedProductManifest.releaseStatus` `BLOCKED`.
- Compatibility `PARTIAL` keeps both release manifests `DRAFT`.
- Validation, quality, and compatibility all `PASS` permit `READY_FOR_REVIEW`, but full package completion also requires the exact ten-image validation and final-ZIP validation to pass.
- `READY_FOR_REVIEW` never creates human approval or publication.

The normal browser and production-matrix flows have no native probe and must remain `PARTIAL`/`DRAFT`. A successful native Excel Desktop 2019+ CLI run can become `PASS`/`READY_FOR_REVIEW`.

## Security boundary

- Contract validation accepts bounded JSON-safe non-cyclic data and rejects unknown fields.
- Workbook parsing is local; formulas/macros are not executed by the Node validator.
- External relationship targets are not followed.
- Native Excel runs with macro automation forced off and link updates disabled.
- Parse/probe failures remain visible and fail closed.

`inspectWorkbook()` is intended for factory-generated bytes, not arbitrary uploads; it has no standalone hostile-upload compressed/uncompressed size policy.

## Evidence and limitations

- `npm run test:production` covers all 1,296 appearance-aware preflight combinations, 28 generated workbook cases, seven required packages, and the five-workbook master sales set without native evidence.
- `tests/workbook-engine.test.mjs` proves exact-byte probe orchestration with an injected test probe, not COM.
- `npm run release:native` is environment-dependent and is not launched by `npm test`.
- The native CLI covers seven required tier/locale/appearance scenarios and a five-workbook master sales set, not the complete active catalog matrix.
- Native formula error scanning and structural checks do not replace independent financial-result validation or full interactive Excel review.
