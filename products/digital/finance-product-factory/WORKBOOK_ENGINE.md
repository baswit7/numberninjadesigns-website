# Workbook engine

## Responsibility

`src/engines/workbook-engine.js` converts a validated product/configuration/catalog selection into XLSX bytes. It creates worksheets, tables, styles, formulas, data validation, conditional formatting, print settings, and formula protection. It does not calculate formulas or launch Microsoft Excel.

`src/factory-runtime.js` is the supported orchestration boundary. It validates inputs, generates and structurally rereads the workbook, optionally calls a compatibility probe on the exact generated bytes, builds quality/compatibility reports, and only then packages the workbook.

## Public API

| Export | Behavior |
| --- | --- |
| `WORKBOOK_ENGINE_VERSION` | Current engine version `1.1.0`. |
| `WORKBOOK_LAYOUT` | Title row 1, instruction row 2, context row 3, headers row 4, data from row 5. |
| `WorkbookGenerationError` | Fail-closed error with stable `code` and optional `details`. |
| `createTranslator()` | Reads one localization bundle and neutralizes spreadsheet formula prefixes. |
| `FORMULA_OPERATIONS` | Frozen registry of 29 workbook formula builders. |
| `buildWorkbook()` | Returns the ExcelJS workbook, resolved context, sheet reports, and metrics. |
| `generateWorkbook()` | Serializes to `Uint8Array` and checks minimum size plus ZIP signature. |
| `expectedSheetNames()` | Resolves the exact ordered translated names used during generation. |

`buildWorkbook()` requires definition, configuration, localization, currency profile, theme, and an ExcelJS runtime. `generatedAt` controls workbook metadata timestamps.

## Generation flow

1. Sort sheets by `order`, then `id`.
2. Translate names, enforce Excel naming rules and case-insensitive uniqueness, and resolve sheet/column maps.
3. Resolve capacity from configuration or sheet declarations.
4. Apply title, instructions, context, headers, widths, number/date formats, panes, filters, print area, and footer.
5. Create tables for non-empty input/data/lookup sheets and map sample values by declared type.
6. Compile only allowlisted structured formulas; lock and hide formula cells.
7. Apply sheet and product validations plus bounded conditional formatting.
8. Protect formula-bearing sheets, request automatic full recalculation, and serialize with styles/shared strings.

Metrics include sheets, rows, columns, tables, formulas, validations, conditional formats, and protected sheets.

## Structural reread

The runtime immediately calls `inspectWorkbook()` on the generated bytes. ExcelJS reread and JSZip/OOXML inspection verify sheet identity/order, live formulas, no `#REF!`, number formats, validations, filters, panes, required parts, relationship targets, and structural metrics.

Failure throws `WORKBOOK_VALIDATION_FAILED` and stops packaging. Structural reread proves a coherent XLSX package; it does not prove native calculation.

## Exact-byte compatibility probe

`FinanceProductFactoryRuntime.generate()` accepts either evidence data or a `compatibilityProbe` function. When a probe is supplied:

1. generation and structural reread complete first;
2. the runtime passes `Uint8Array.from(generated.bytes)`, the definition/configuration, validation report, and timestamp to the probe;
3. the returned target evidence builds the compatibility report;
4. quality scoring and packaging occur afterward;
5. the package engine snapshots the original generated workbook bytes.

`tests/workbook-engine.test.mjs` hashes the probe input and proves the runtime and package contain that same byte sequence.

The certified production implementation is `scripts/generate-native-release.mjs`. Its probe writes the exact generated bytes, runs Excel COM recalculation/open-save checks, structurally rereads Excel's save-copy, and returns evidence only for `excel-desktop`. The CLI then rechecks that the original tested hash is unchanged and present in the package. The Excel save-copy is evidence; it is not substituted for the packaged source workbook.

## Certified target and status

Current product definitions declare only `excel-desktop`, with minimum Excel version 2019 and recalculation required. Excel for the web, LibreOffice, and Google Sheets are not release-certified.

- Browser/default generation has no native probe: compatibility `PARTIAL`, generated/release manifests `DRAFT`.
- A successful native CLI probe can produce compatibility `PASS` and `READY_FOR_REVIEW` manifests.
- The engine does not grant human approval or perform external publication.

## Formula and validation behavior

The 29 operations are documented in [FORMULA_ENGINE.md](FORMULA_ENGINE.md). Unknown operations, references, targets, conditions, or unsafe output throw. `fillDirection: "down"` compiles through sheet capacity; other modes write one target. Each formula receives cached result zero and requires target-application recalculation.

Implemented validations include required, list, date, decimal, whole, text length, range, and restricted custom formulas. Inline list text over 240 characters is rejected.

## Styling and security

- Theme colors/fonts drive workbook styling; input and calculated cells remain distinct.
- Currency formats come from the currency profile and dates from localization.
- Worksheet print settings come from `SheetDefinition.print`.
- Text beginning with `=`, `+`, `-`, or `@` after whitespace is apostrophe-prefixed.
- Sheet names, references, operations, conditions, and validation text are bounded or allowlisted.
- Protection password `nnt-input-safe` prevents accidental edits; it is not encryption or access control.
- The engine and browser runtime perform no network request.

## Current limitations

- ExcelJS does not calculate formula results; only native Excel performs the certified recalculation gate.
- The native CLI covers seven required tier/locale/appearance scenarios, not the entire 1,296-case catalog matrix, all active products, or all capacities.
- The CLI records but does not numerically enforce the Excel 2019+ version floor.
- `fillDirection: "right"` has no horizontal implementation; `inputRowsBound` is ignored.
- Contract-valid formula `args` are not consumed by workbook builders.
- Formula protection and structural/native error checks do not replace independent financial verification.
- `inspectWorkbook()` is intended for factory-generated bytes and has no hostile-upload ZIP expansion policy.
